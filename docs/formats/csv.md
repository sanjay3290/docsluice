# CSV and TSV

CSV and TSV are decoded using the shared text encoding detector and emitted as tables of at most 1,000 rows: a file of up to 1,000 rows is one table, and a larger file is several consecutive tables whose cell addresses continue (`A1001` starts the second). CSV chooses comma, semicolon, tab or pipe by the most consistent nonzero delimiter count among the first 50 physical lines outside quoted fields. TSV always uses tab. Quoted fields support delimiters, doubled quotes and line breaks; a leading BOM is skipped. Empty physical lines are ignored, while ragged rows are padded to the widest row of their table. Cells use spreadsheet addresses from `A1` through `XFD` and padding counts toward the shared `cells` budget. `headerRows` remains `0` until header detection is specified.

Malformed quoting produces `UNREADABLE_PART` without including file content in the warning. An input, cell or output limit produces a `TRUNCATED` warning and a partial table. The reader caps parsing at the configured cell and output allowances; it does not allocate rows or columns from a file-declared dimension.

Delimiter sniffing is limited to an 8 KiB prefix. The reader then decodes the supplied byte array in 64 KiB chunks and stops decoding when a cell or output limit is reached. The incremental tokenizer preserves CRLF, doubled quotes and split UTF-8 code points. Each table is emitted as soon as its rows are parsed, and the reader then awaits `out.flush()`, so with `extractStream()` a slow consumer pauses parsing and memory stays bounded by the stream's high-water mark (EXT-2). The reader still receives the complete input bytes; incremental input reading (IN-10) is a follow-up.

`extract()` loads this reader lazily for `csv` and `tsv` input. It is also available as the `docsluice/csv` (`csvReader`, `tsvReader`) and `docsluice/tsv` (`tsvReader`) subpaths.
