# OpenDocument Text (ODT)

The ODT reader (`docsluice/odt`, detected from the package `mimetype`) extracts paragraphs in document order, outline headings, nested lists, tables with covered/merged cells, footnotes, endnotes, comments (`office:annotation`, emitted as `note` blocks with role `comment`, as in DOCX), and image descriptions. It reads `content.xml`, `styles.xml`, `meta.xml`, and `META-INF/manifest.xml` from the package. Unknown extension subtrees are ignored as content. Heading levels inherit from the ODF paragraph style when the heading does not declare an outline level. Declared list styles supply basic numbered, alphabetic, and bullet markers; complex counter formats are simplified. Nested lists beyond the configured block-depth limit are flattened into their owning item while retaining paragraph text and emitting `DEPTH_LIMIT`.

Image blocks retain alternate text and known frame dimensions. An internal image reference is accepted only when its literal, undecoded package path appears in the manifest and matches an exact ZIP entry. The child is listed with its declared media type and size; child bytes are retained only when `childBytes` is enabled. External link targets are reported as data, never fetched. Encrypted package parts cause a password-required error because this reader does not decrypt ODF content.

Tracked changes use the shared `revisions` option: `accept` includes insertions, `reject` includes deletions, and `show` brackets both (`[+inserted+]` and `[-deleted-]`). Both inline wrappers and the ODF change catalog with point and range markers are resolved. Stored catalog history is not emitted as ordinary body text. The reader emits a static `HIDDEN_CONTENT` warning whenever tracked changes occur. XML DTDs are ignored by the shared XML parser. Metadata privacy follows the shared `metadata: false` behavior, including comment authors.

Tables use the same grid as DOCX: every row lists one cell per grid column, a spanning cell carries `colSpan`/`rowSpan`, and each covered position (`table:covered-table-cell`) is an empty cell. `table:number-columns-repeated` repeats a cell up to 1,024 times, and each copy is charged to the `cells` limit. A table nested in a cell adds its paragraph text to that cell's text, and the nested table is also emitted as its own block after the containing table. Rich list numbering labels, text boxes, drawing objects beyond linked images, and ODF encryption are not interpreted.

The corpus holds LibreOffice-made ODT twins of the DOCX fixtures (`corpus/odt/`, built from `scripts/corpus/src/*.fodt`). `test/odt/parity.test.ts` checks that each pair gives the same blocks. Image references differ because the package layouts differ.
