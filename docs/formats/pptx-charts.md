# PowerPoint charts

PPTX chart parts can be represented as tables from their embedded cached series. Bar, line and pie chart series are read only from the direct `c:chart/c:plotArea` path and their `c:ser` category and value reference caches (`c:strCache` and `c:numCache`). A chart table has a `Category` column followed by one column per cached series label. Cache points are aligned by their `idx`; missing indexes become empty cells, and `ptCount` is ignored so it cannot cause an allocation by itself. Cell text preserves the cached string; finite numeric caches also include the parsed number in the cell's `raw` value. Text caches do not have a `raw` value.

The reader does not evaluate chart formulas or fetch linked workbooks. It only uses values already cached in the chart part. Formula-only series labels use deterministic `Series N` labels. Charts without supported chart types or cached points produce no table. Literal-only caches, chart titles and multi-level categories are not currently included.

Retained table cells are charged to the shared budget once. Parser text is reserved against the shared output-character limit across all returned tables, while the document builder charges characters when it emits the tables. Caller limits in truncate mode keep the header and complete rows that fit, then set the document's truncated state. After the shared XML parser has allocated the source tree, the chart helper applies independent hard caps of 500,000 source objects (including attribute entries) and 20,000,000 characters (including attribute names and values). These caps include unused extension content and series caches so unused or repeated source data cannot bypass staging limits; the helper caps subsequent cache/table retention and do not replace the archive and shared XML parser limits.
