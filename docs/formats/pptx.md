# PowerPoint presentations

The `.pptx` reader follows the package `officeDocument` relationship to the presentation part, then reads slides in `p:sldIdLst` order. Each slide becomes a `slide` section; only `title` and `ctrTitle` placeholders set the section title and produce a heading. Text shapes are ordered by transformed vertical position, then horizontal position, then their order in the slide XML. Group transforms and inherited layout/master placeholder positions are applied where present. Body text and explicit DrawingML bullets are represented as lists; DrawingML tables become table blocks, and SmartArt diagram data is emitted as a text list.

Shape traversal is iterative and shares the configured block-depth budget. XML parsing shares the XML-depth and archive budgets, while structural XML text is not charged as emitted `outputChars`; a local cap limits each presentation part to 500,000 retained XML elements and 20 million XML text/source-work units. Table cells consume the shared cell budget, including empty cells. Other local safety caps bound retained shapes, paragraphs, and SmartArt items. Invalid optional slide parts are skipped with a static `UNREADABLE_PART` warning. Hidden-slide behavior is not specially interpreted.

This reader does not yet extract speaker notes, chart cached values, images, or embedded objects. Chart relationships are not followed for content. Shape rotation and flip metadata are not applied to ordering coordinates. The synthetic CC0 unit fixtures in `packages/docsluice/test/readers/pptx/fixtures/` cover relationship ordering, title placeholders, geometric ordering and ties, inherited placeholder coordinates, group transforms, tables, SmartArt, and hostile nesting. Full LibreOffice corpus goldens and the public detection pipeline remain separate acceptance work.
