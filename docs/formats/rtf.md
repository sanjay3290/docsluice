# Rich Text Format (RTF)

The RTF reader extracts text in document order from the plain-text control stream. It supports ANSI/code-page declarations, font `fcharset` selection, hex byte escapes (`\\'hh`), signed `\\uN` values with `\\ucN` fallback skipping, paragraph and line breaks, bold and italic runs when `runs: true`, outline-level and common heading-style controls, simple lists, and basic tables. It also reads title, author, subject, keywords, comments, and valid creation or revision timestamps from `\\info`.

The reader skips formatting tables and unknown starred destinations. It skips `\\binN` payloads by the declared count without allocating that size, and reports an `UNREADABLE_PART` warning if the count exceeds the remaining input. `\\pict` becomes an image placeholder with `image/unknown`; picture bytes are not decoded or attached. `\\object` only sets `features.hasEmbeddedFiles`; embedded objects are never executed or extracted. Group parsing is iterative and bounded by `blockDepth`; excess nesting is skipped with `DEPTH_LIMIT`.

Code-page mappings include Windows-1250 through Windows-1258, Windows-874, IBM 437/850, Shift-JIS, GBK, EUC-KR, Big5, and UTF-8. Other code pages fall back to Windows-1252 with `ENCODING_GUESSED`. The runtime's `TextDecoder` must support the selected label.

The reader module also exports `deencapsulateRtfHtml(bytes, budget)` for MSG body reconstruction. It follows the [MS-OXRTFEX recognition](https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-oxrtfex/3cf14977-3883-404a-8ed8-57c99263fb76) and [HTML extraction](https://learn.microsoft.com/en-us/openspecs/exchange_server_protocols/ms-oxrtfex/906fbb0f-2467-490e-8c3e-bdc31c5e9d35) rules for `\\fromhtml` in the first ten RTF tokens, `\\htmltag` fragments, ignored `\\mhtmltag` fragments, and `\\htmlrtf` suppression. It applies the shared work, depth, and output budgets and returns `undefined` for ordinary RTF or if bounded extraction cannot complete. The returned HTML is inert text; callers must pass it through their normal safe HTML reader and must never execute it.

This is a text extractor, not a layout-preserving RTF renderer. Bullet markers and nested list levels are inferred from common paragraph controls, but list-table numbering definitions are not resolved; emitted lists are currently unordered. Table rows and cells are retained, simple horizontal and vertical merge spans are recognized, and complex merge geometry and nested tables are not reconstructed. Headers and footers are retained as header/footer blocks. Hyperlinks, fields, tracked revisions, footnotes, comments as note blocks, and full style-sheet interpretation are not implemented. RTF is not yet wired into the public `extract()` registry in this foundation snapshot.
