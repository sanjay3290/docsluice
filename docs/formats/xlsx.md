# XLSX

The XLSX reader follows workbook relationship order to locate worksheet parts. It retains each sheet's visible, hidden, or very hidden state in its parsed representation and emits an `UNREADABLE_PART` warning for unresolved package parts. Hidden sheets produce `HIDDEN_CONTENT` warnings and carry the matching `hidden: true` or `hidden: 'very'` state on their emitted section.

Styles resolve through the workbook's styles relationship. Numeric cells are formatted with the custom or built-in number format mapped by `cellXfs`, using `workbookPr/@date1904` for calendar serials; `raw` retains the stored numeric value. Text cells pass through the format's text section when present. Formulas are not evaluated.

Cells are parsed into sparse maps keyed by numeric row and column coordinates. The worksheet `dimension` declaration is ignored when calculating output ranges. Output tables are made from contiguous horizontal cell runs; matching runs on adjacent rows merge into a rectangular table. Disconnected runs become separate tables, so distant cells such as `A1` and `Z90000` do not allocate the rectangle between them. Every populated cell carries its A1 address; table and sheet locations carry the sheet name, and table locations carry the range.

Shared strings, rich-text runs, inline strings, booleans, errors, stored string values, and ISO date values are read as stored. Rich runs are flattened. Numeric cells expose deterministic display text and use a finite numeric `raw` value when conversion is safe. Dates use calendar arithmetic with no host timezone conversion. A malformed or out-of-range style index falls back to General with one generic warning per worksheet. Formulas are never evaluated.

The reader charges unique worksheet cells against the shared cell budget. Shared strings are streamed separately and retained under fixed 500,000-entry and 20-million-character caps; they do not consume worksheet-cell or emitted-output counters until referenced cells are staged. Parser/table staging has a separate 1.5-million-object cap, sized to support ordinary 100,000-row sheets while bounding retained workbook structures. Sheet names have independent source caps; the caller's output-character quota is applied when each actual section title is staged. Dense table expansion is bounded by the actual populated contiguous regions. A cell or output-character limit stops retained cell output and marks the document truncated; warning details include per-sheet retained and skipped row and cell counts when cell records were skipped.

The test fixtures include the self-authored LibreOffice 421-case number-format workbooks and a LibreOffice-saved workbook with decimal/date formats, alongside synthetic parser inputs. LibreOffice expected strings are compared only where the documented 1900 epoch and width-padding behavior agree; this is not Excel cross-validation.
