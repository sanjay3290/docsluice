# XLSX

The XLSX reader follows workbook relationship order to locate worksheet parts. It retains each sheet's visible, hidden, or very hidden state in its parsed representation and emits an `UNREADABLE_PART` warning for unresolved package parts. Hidden sheets produce `HIDDEN_CONTENT` warnings. `DocBuilder.openSection()` currently has no hidden-state setter, so the emitted public section cannot yet carry that state; the lead integration must add the API before XLS-1 is complete.

Cells are parsed into sparse maps keyed by numeric row and column coordinates. The worksheet `dimension` declaration is ignored when calculating output ranges. Output tables are made from contiguous horizontal cell runs; matching runs on adjacent rows merge into a rectangular table. Disconnected runs become separate tables, so distant cells such as `A1` and `Z90000` do not allocate the rectangle between them. Every populated cell carries its A1 address; table and sheet locations carry the sheet name, and table locations carry the range.

Shared strings, rich-text runs, inline strings, booleans, errors, stored string values, and ISO date values are read as stored. Rich runs are flattened. Numeric cells retain their stored string in `text` and use a finite numeric `raw` value when conversion is safe; number formats are applied by the separate XLSX formatting work. Formulas are never evaluated.

The reader charges unique worksheet cells against the shared cell budget. Shared strings are streamed separately and retained under fixed 500,000-entry and 20-million-character caps; they do not consume worksheet-cell or emitted-output counters until referenced cells are staged. Parser/table staging has a separate 1.5-million-object cap, sized to support ordinary 100,000-row sheets while bounding retained workbook structures. Sheet names have independent source caps; the caller's output-character quota is applied when each actual section title is staged. Dense table expansion is bounded by the actual populated contiguous regions. A cell or output-character limit stops retained cell output and marks the document truncated; warning details include per-sheet retained and skipped row and cell counts when cell records were skipped.

Synthetic fixtures under `test/readers/xlsx/fixtures/` cover relationship order, sheet states, sparse ranges and malformed shared-string indexes. They are self-authored parser inputs, not golden compatibility evidence. LibreOffice/Office corpus goldens remain dependent on the separate corpus pipeline.
