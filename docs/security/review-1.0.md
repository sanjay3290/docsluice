# Pre-1.0 security review (partial)

**Readiness: INCOMPLETE — NOT READY FOR 1.0.** This is a scoped review of foundation commit `a3b45f12429216d72fb3cb3e21955d5947b38c0d`, performed 2026-10-09. It is not a certification of every reader or format. The baseline registers only the legacy `doc` reader in [`core/registry.ts`](../../packages/docsluice/src/core/registry.ts#L42-L48); PDF, DOCX, XLSX, PPTX, email, and the other planned readers are absent from this commit. Consequently, the issue’s request to review every reader and the release acceptance criteria cannot be completed against this baseline.

The checked-in evidence covers source under `packages/docsluice/src/`: core input, limits, budgets, extraction/building, detection, ZIP, XML, OLE/CFB, the legacy binary DOC reader, renderers, and the Node entrypoint. Requirements are evaluated only for those files and for parser-level tests available at the cited commits. No changes to parser code, dependency policy, package metadata, lockfile, security policy, or CI were made for this review.

## Findings and readiness blockers

| ID | Severity / status | Finding and required action |
|---|---|---|
| SEC14-1 | **Moderate — open** | The pinned production dependency is `fflate@0.8.2`. The lockfile-only npm audit reported [GHSA-px8p-9vwx-vf98](https://github.com/advisories/GHSA-px8p-9vwx-vf98), a denial-of-service advisory affecting `fflate` versions below 0.8.3, with 0.8.3 listed as a fix. The inspected ZIP reader imports the streaming `Inflate` API rather than `unzipSync`, the API named in the advisory; exploitability through this use was not demonstrated. Keep this finding open and have the dependency owner update the pin to a patched version, rerun parser/hostile tests and the audit, and confirm the lockfile resolves the package used by the library to at least 0.8.3. This review does not change dependencies. |
| SEC-REVIEW-1 | **Release blocker — open** | The baseline has no registered PDF, OOXML, spreadsheet, presentation, email, or other planned readers. Findings for those parsers cannot be inferred from ZIP/XML primitives or fixture recipes. Complete the per-reader review after their registration and hostile tests land; blockers named by issue #80 include #45, #29, #34, #37, and #52. |
| SEC-FUZZ-1 | **Release blocker — open** | Available fuzz evidence is short smoke evidence only: the separate #22 candidate ran five targets (`zip`, `xml`, `detect`, `detection`, `ole`) for two seconds each. There is no evidence of seven consecutive nightly runs with zero open crashes, and no DOC/PDF/Office/email reader target is covered. The #22 evidence is in the separate commit `9b4541f809b9f72fde935d145ec06986ca40c2bb`; it is not part of this review baseline. Do not mark the seven-night criterion complete. |
| SEC-HOSTILE-1 | **Coverage blocker — open** | The separate #20 candidate (`6f303cdafe7ae92a68c1bd91b72ed427609ff093`) adds 27 synthetic hostile inputs tagged for SEC-1–SEC-10 and parser-level ZIP/XML tests. Those inputs and observations are not integrated into this baseline’s root hostile manifest or extraction runner. They demonstrate selected parser behavior, not all-reader extraction behavior, global prototype/network invariance across extraction, or compliance with the SEC-6 every-format requirement. |
| SEC13-1 | **Not implemented in this baseline** | PRD SEC-13 describes optional Node worker isolation. The Node entrypoint here re-exports the core API and there is no `src/node/worker` implementation. This is a missing optional defense, not a finding that the current parsers execute in a worker. Decide whether it is a 1.0 requirement and, if so, land and review it separately. |

The 2026-10-09 npm audit snapshot reported zero high and zero critical advisories, one moderate advisory, and no low advisories for both production-only and all locked dependencies. That is a dated dependency result, not a claim that the library has zero high/critical security risks: reader coverage, integration, multi-night fuzzing, and hosted CI remain unverified. Production and all-dependency JSON reports are preserved under [`evidence/`](evidence/).

The separate #20 parser suite exercised ZIP many-entry and ZIP64 count-lie inputs. No all-reader hostile runner exists in this baseline. |

| SEC-5 — entity expansion and XML depth | **Implemented in shared XML scanner; parser-level evidence** | The scanner decodes only the five built-in named references and numeric references; unknown named entities remain unexpanded ([tokenizer.ts](../../packages/docsluice/src/xml/tokenizer.ts#L254-L289)). Text/output and element depth are checked ([tokenizer.ts](../../packages/docsluice/src/xml/tokenizer.ts#L319-L327), [tokenizer.ts](../../packages/docsluice/src/xml/tokenizer.ts#L550-L564)). This is not an independent security scanner and says nothing about absent readers. |
| SEC-8 — deep nesting | **Iterative walks and limits in inspected core/XML/CFB/DOC paths** | XML tree building uses an explicit stack ([tree.ts](../../packages/docsluice/src/xml/tree.ts#L10-L34)); XML, block, and child-depth limits are charged by the budget ([budget.ts](../../packages/docsluice/src/core/budget.ts#L159-L187)). | SEC-9 — loops and reference cycles | **Global timeout and visited checks in reviewed primitives** | The extraction wrapper races work against a timer that aborts the shared signal ([extract.ts](../../packages/docsluice/src/core/extract.ts#L321-L350)); `Budget.tick()` checks time and cancellation ([budget.ts](../../packages/docsluice/src/core/budget.ts#L159-L165)). | SEC-11 — active content and formulas | **No execution API found; reader behavior incomplete** | A source scan found no `eval`, `new Function`, or equivalent active-code execution in the inspected package source. | SEC-14 — supply chain | **Pinned lock; moderate advisory open** | The lockfile pins the library’s `fflate` dependency at 0.8.2 and `npm ci --ignore-scripts` succeeded. ## Hostile corpus and fuzz evidence

The #20 candidate prepared 27 small CC0 fixtures, generated by its reproducible script. Its 16 parser-level hostile tests passed in the captured run. Coverage includes ZIP ratio/entry/path/overlap/ZIP64 cases and XML XXE/entity/depth/prototype-shaped attributes, plus JSON/CSV/HTML inputs as data. It does not run `extract()` against all files, and its manifest delta is not the root hostile manifest. See `/workspace/package-a-prep/hostile20-integration.md`, `/workspace/package-a-prep/issue20-verify.log`, and `/workspace/package-a-prep/issue20-regressions.log` for the associated handoff evidence.

The #22 candidate has five parser fuzz targets and a watchdog/memory-bounded runner. On 2026-10-09, all five two-second smoke targets passed with coverage feedback (`/workspace/package-a-prep/fuzz-evidence/five-target-smoke.log`); the runner regression tests passed 7/7 with an isolated `@jazzer.js/core@4.0.0` install (`/workspace/package-a-prep/fuzz-evidence/regression-tests.log`). The tests do not show seven consecutive nightly runs, and the target set does not include the missing readers. The #22 handoff records that package/lock/script registration was parent-owned and pending at its review time. Fuzz CI registration and the seven-night acceptance criterion must be independently confirmed before release.

## Release decision

Keep this review marked incomplete. Do not treat the acceptance criteria for #80 as met. The owner must resolve or formally disposition SEC14-1, integrate and audit every supported reader, register hostile extraction tests and reader fuzz targets, produce seven consecutive nightly fuzz records with no open crashes, and confirm hosted CI before making a 1.0 security-readiness claim.
