# Independent review: final private PDF helpers

**Scope:** read-only review of layout in `/workspace/docsluice-package-e-46`, plus header/footer and table staging in `/workspace/docsluice-package-e`. Focus was hostile values, allocation/work bounds, deterministic behavior, and heuristic correctness. These helpers are not public readers or parser integrations. The PDF engine/adapter, licensed real-PDF corpus/goldens, and acceptance accuracy remain pending; this review does not claim #46 or PDF support accepted.

## Focused verification

- In the #46 worktree: `node ../../node_modules/vitest/vitest.mjs run test/readers/pdf/layout/layout.test.ts` — **25/25 passed**.
- In the combined worktree: `node ../../node_modules/vitest/vitest.mjs run test/readers/pdf/headers/headers.test.ts test/readers/pdf/tables/tables.test.ts` — **33/33 passed**.

## Findings

1. **Vertical-direction text is silently dropped by layout.** The latest `normalizeItem` now rejects directions outside `ltr`/`rtl`. PDF.js text items may report `ttb`; that input disappears without warning. The docs mention vertical writing can be ambiguous, but do not say it is discarded. Either state an adapter-level exclusion with a bounded warning/count, or retain it in a separate deterministic path. Suggested regression: one `ttb` item mixed with horizontal items, assert explicit skip/warning or preserved source text and stable index.

2. **Layout abort/timeout coverage is only immediate-abort in the tests.** Sorting comparators and iteration loops tick the shared budget, so the implementation has cancellation/time checkpoints; long native operations such as `normalize()` (headers), per-cell joins, and large string trims run between ticks. Per-line caps and the table's 100k input/65,536-cell caps bound those operations, but the layout has no explicit item-count cap. Suggested stress regression: large input with small `timeMs` and an abort triggered during scanning/sort; confirm prompt `TimeoutError`/`AbortError` and no fallback catch. Also test all-empty items to ensure time—not text allowance—stops work.

3. **Budget preflight appears deliberately staged, not charged.** Layout checks existing `outputChars` plus staged chars and emits a safe prefix on output truncation; tables and header/footer similarly call `checkOutputChars` without charging, leaving actual emission to the builder. Table cell counts are planned against remaining `cells`, and an overrun is routed through `addCells` to trigger the configured limit behavior before occupancy allocation. Header/footer preflight failure returns original page lines unchanged. These semantics are internally consistent with staging, provided the eventual builder charges each emitted text/cell exactly once and integration stops further work after shared truncation. Suggested integration regression: pre-charge part of `outputChars`, stage a page/table/header pass near the limit, then verify the builder neither double-counts nor emits beyond the remaining allowance.

4. **Geometry limits are present, but malformed metadata policy is uneven.** Layout rejects nonfinite and excessive page/item geometry, unsupported rotations, malformed transforms, and now invalid direction values; table staging rejects invalid dimensions/coordinates and caps source-index arrays/grid work; header/footer checks page and line geometry before classification. These are useful bounds. Add tests for negative width/height, huge finite-but-over-bound page dimensions, negative/out-of-range line extents, and invalid/duplicate page indices across all helpers to lock the current conservative behavior.

5. **Header/footer matching is deterministic and conservative, but normalization deserves one adversarial fixture.** Group keys use role + NFC text with whitespace collapsed and decimal runs replaced by `#`; position buckets search neighbors and select closest anchor with stable first-order tie-break. Quorum counts distinct page indices; all-page and parity thresholds require three pages and 60%. Tests cover threshold, parity variants, position mismatch, output preflight, cancellation, and immutability. Suggested test: same normalized header text with two anchors straddling bucket boundaries, delivered in reversed page/line order; assert deterministic, non-bridging groups. This probes first-anchor grouping where near-tolerance chains could otherwise depend on encounter order.

6. **Table detection intentionally trades recall for precision.** Ruled tables require complete rectangular connected cells; incomplete geometry is ignored. The unruled detector needs separately positioned cell-level lines and at least three aligned rows, so it cannot split text merged into a whole row by layout. Existing synthetic tests make exact assertions for 2×2 ruled and 3×2 aligned cases, including source indices, plus malformed rules, boundaries, duplicate rules, limits, and immutability. Before acceptance, add independent goldens for merged/spanning cells, partial/near-collinear rules, multiple tables, text touching borders, and repeated header-like rows. Do not read the 0.72/0.55 values as calibrated confidence until compared with the hand-reviewed corpus.

7. **No critical allocation based on untrusted table declarations found.** Grid dimensions derive from capped unique coordinates and `MAX_GRID_CELLS`; complete cells are counted before occupancy-array allocation; text is preflighted before cell joins. Header strings are individually capped at one million UTF-16 units before normalization, and normalization ticks per character. The remaining outer collections scale with supplied page/line arrays (which are already resident); the future adapter must enforce page, line, and text budgets before handing them to these helpers.

## Acceptance limits

All results are synthetic unit-helper evidence only. The helpers assume validated engine text/geometry and do not establish parser correctness, network/worker/eval behavior, page order on real PDFs, OCR behavior, extraction accuracy, or runtime compatibility. Require #45 adapter integration, #27 licensed corpus/goldens, and the ten-page accuracy gate before a full #46 acceptance claim. No source files were changed.
