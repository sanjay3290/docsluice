# Synthetic PDF layout source fixture

`generate.py` uses only Python's standard library to create a deterministic,
original, ten-page PDF at a requested output directory. It is a preparation
fixture for probing the private PDF layout, header/footer, and table helpers.
It is not a PDF extraction golden and does not establish reader acceptance or
accuracy.

The pages cover one, two, and three columns; a full-width title; font-size
heading; bottom footnote; separately positioned superscript; a line-end
hyphenation case; a 90-degree rotated page; a ruled 2x2 table; and an aligned
unruled 3x2 table. Each page also has a repeated running header and a numbered
footer that alternates ODD/EVEN. The two- and three-column content streams are
interleaved to distinguish stream order from the manually authored layout
reference. The ten-page `independentLayoutOrderReference` is a source-fact
sequence for later comparison, not a claim that a particular reader will
produce that output.

The PDF uses standard Type 1 Helvetica and ASCII source text only. The rotated
page retains a 612x792 media box and sets `/Rotate 90`; its expected displayed
geometry is recorded separately. The table page records the explicit line
coordinates and expected source cells. All generated PDFs have a sidecar with
`CC0-1.0` provenance. Artifacts are small and regenerated byte-for-byte by the
stdlib generator.

Run the structural and optional Poppler checks with:

```sh
python3 generate.py /tmp/layout-pdf-fixtures
python3 -m unittest -v
```

Tests validate generated bytes, classic xref offsets, page count, rotation,
text operators, source facts, determinism, and sidecars. When `pdftotext` is
available, it independently confirms the file can be parsed and that expected
source phrases are visible; this still does not test docsluice extraction.
No output goldens are included. After the approved PDF engine is available,
compare actual output to the source facts and assign outcome/warning metadata
only from those runs.
