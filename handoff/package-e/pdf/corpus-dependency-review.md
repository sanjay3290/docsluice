## Provenance and manifest status

The 10 PDF files in `corpus/pdf/` are generated from authored CC0 FODT/FODP sources under `scripts/corpus/src/`. Each has an SPDX CC0-1.0 sidecar recording LibreOfficeDev version, source path, and requirement tags. The encrypted sidecar intentionally publishes the fixed test password `docsluice-fixture-only`; it is synthetic test data, not a credential. `scripts/corpus/manifest-delta.json` has 34 output records total, 10 PDF records, all marked `goldenStatus: "unreviewed"`. There are no PDF JSON/Markdown golden files or PDF reader tests at this commit, and no `packages/docsluice/src/readers/pdf/`; ADR 0009 remains Proposed. Thus these source facts can guide owner review, but do not justify approving implementation goldens before the engine/reader and their behavior are reviewed.

Evidence tools: Poppler `pdftotext 25.03.0` / `pdfinfo 26.05.0`, pypdf `6.10.0`, LibreOfficeDev `26.8.0.0.alpha0 2c87e51eeaa2b413ff4ae097b2705eea1995d8e5`, Tesseract CLI, and a throwaway byte-only `unpdf@1.7.0` parse (bundled PDF.js `5.6.205`) with `isEvalSupported:false`, `useWasm:false`, `useWorkerFetch:false`, `disableAutoFetch:true`, `disableStream:true`, and `disableRange:true`. These are local inspection results, not an accepted engine result or complete #44 runtime validation. PDF reader options and output semantics may differ from these tools.

## Gaps before owner approval

1. **No custom page-label fixture.** The only observed labels are decimal defaults; `headings-outline.pdf` has an outline and link but no `/PageLabels` number-tree. #45's current issue snapshot explicitly requires labels including roman/prefix/start-value cases and golden tests on multi-page, labels, outline, links, and scanned inputs. Add a small authored PDF with an explicit `/PageLabels` dictionary and source-fact test before treating label parsing as covered.
2. **Metadata fixture is incomplete for #45.** Across the 10 PDFs, Info metadata only had Creator, Producer, and CreationDate. The source titles were not exported as `/Title`; no `/Author` was present. Add an authored PDF with explicit Info/XMP title, author, date, and language fields if those are to be golden-tested. None of the 10 PDFs has form fields (`pypdf.get_fields()` is empty for all), so they do not cover PDF-7 forms/sticky notes either.
3. **Encryption coverage is partial for #47.** The new file correctly covers a nonempty user password with no/wrong/correct password. The current #47 snapshot also requires an owner-password-only file that opens with an empty user password; this export uses `DocumentOpenPassword`, so it does not cover that case. Add an owner-only fixture separately; do not mark #47 complete from this one.
4. **Do not conflate source Office features with PDF features.** PDF export flattens lists, tables, revisions, groups, and omits speaker notes/hidden slides. `deck-12-slides.pdf` is 11 pages. Restrict PDF expected output to actual PDF text/items, page count/order, outlines, annotations, metadata, image-only detection, and encryption behavior. Keep XLS/ODF/PPT-specific feature expectations on their native outputs.
5. **Stale README count.** `scripts/corpus/README.md` still says 32 candidate files / eight PDFs after this commit adds two PDFs; `manifest-delta.json` counts 34 / 10. Update that prose in the corpus PR.
6. **Golden approval is blocked by absent reader/engine decision.** No PDF reader or goldens exist at this commit. Candidate text and structural facts above are useful review evidence, but #44/ADR 0009 remains unaccepted and #45 lists #44/#10/#27 blockers. Do not check these into reviewed goldens or call the PDF criteria complete based on Poppler, pypdf, or the throwaway unpdf parse.

The two new PDF sidecars accurately cite authored CC0 sources. The scanned-image fixture is especially useful because independent extraction confirms no selectable text despite visible OCR-readable content. The encrypted fixture is also a valid password-protected PDF, with the narrower coverage limitation above. The remaining old candidate PDFs are lawful synthetic CC0 outputs, but several source requirements do not survive PDF export and their manifest tags should remain intent tags, not claims of supported/verified features.
