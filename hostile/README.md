# Hostile corpus

Attack files that every reader must survive. Layout and `manifest.json` format: [docs/testing.md](../docs/testing.md#3-hostile-tests-qa-3-section-143).

`zip/nested-4gib.zip` is the real-output bomb recipe: its outer ZIP contains a compressed inner ZIP64 archive whose DEFLATE member represents exactly 4 GiB of zero bytes. Regenerate it with `node scripts/hostile/zip-nested-4gib.mjs`; the script streams 64 KiB chunks through Node zlib and writes only the 42 KiB outer fixture. The generator records the exact logical input and CRC values in its output.

## Where each file comes from

Every file is generated by a script, so the repository holds the recipe as well as the bytes. Regenerating is deterministic and leaves the files unchanged.

`packages/docsluice/test/hostile.test.ts` runs every manifest entry through `extract()` with default options in `npm test`. An optional `format` forces the reader. The runner fails on a wrong error or warning list, on exceeding `maxMs`, on any new key on `Object.prototype` or `Array.prototype`, and on any `fetch` call. It also fails when a file in this folder has no manifest entry. Entries for formats without a reader yet record the current safe outcome, usually `UNSUPPORTED_FORMAT`; the issue that adds the reader updates them.
