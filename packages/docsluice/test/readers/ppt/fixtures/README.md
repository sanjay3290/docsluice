# PPT source and hostile fixtures

`order-title-notes.fodp` is the self-authored CC0 source of the committed LibreOffice PPT. Export it with:

```sh
soffice -env:UserInstallation=file:///tmp/docsluice-ppt-export --headless --convert-to 'ppt:MS PowerPoint 97' --outdir corpus/ppt packages/docsluice/test/readers/ppt/fixtures/order-title-notes.fodp
```

The committed export was made with LibreOfficeDev 26.8.0.0.alpha0, commit `2c87e51eeaa2b413ff4ae097b2705eea1995d8e5`. Binary office exports may include generated timestamps; byte-identical export regeneration is not asserted. The reviewed direct-reader JSON golden checks the committed bytes. It includes one title placeholder, three ordered slides, Unicode text and speaker notes. The second and third title-like shapes export as ordinary text.

`build_hostile.py` mutates only known stream fields in that trusted export, producing three hostile PPT files in `hostile/`. `--check` compares generated bytes without modifying committed fixtures. Their expected outcomes are `CORRUPT_FILE` for invalid edit offsets and oversized persist runs, and `ENCRYPTED` for the encrypted-user token. The direct-reader tests exercise these files; the integration lead receives manifest entries and can move or register the files with the shared hostile runner.

The recipe is a test-only locator for this known CFB input. It does not ship in the library and is not a general CFB parser.
