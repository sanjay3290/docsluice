# LibreOffice corpus preparation

These synthetic sources are dedicated to CC0-1.0. They contain no private or third-party documents.

Run from the repository root with LibreOffice installed on macOS or Linux:

```sh
node scripts/corpus/build.mjs
node --test scripts/corpus/build.test.mjs
```

Use `--soffice "/path/with spaces/soffice"` or `SOFFICE` for a non-default executable. `--output DIR` selects a separate destination, and `--timeout-ms 60000` sets the conversion watchdog. A fresh isolated LibreOffice profile is used for each conversion. The tool generates 38 files: four each in DOCX, ODT, RTF, XLSX, ODS, PPTX and ODP, plus ten PDFs. The committed files were built with LibreOffice 24.2.7.2 on Linux; each `.license` records the version used.

Re-running the build gives the same documents with different timestamps and tool-generated identifiers: ZIP entry times and `meta.xml`/`docProps` dates, ODF `RsidRoot`/`Rsid` settings and tracked-change IDs, PowerPoint field GUIDs, and PDF creation dates and document IDs. Text, structure and features do not change. Because the files are committed, goldens never depend on a rebuild.

Each output receives a CC0 license sidecar recording the LibreOffice version, source path and intended requirements. `scripts/corpus/manifest-delta.json` is the inventory of the committed outputs: sizes, SHA-256 hashes and `goldenStatus: "unreviewed"` until a reader adds reviewed goldens. Source tags associate a fixture with a requirement; they do not assert reader support. Until a format has a reader, the golden runner requires each of its files to fail with `UNSUPPORTED_FORMAT` (see docs/testing.md).

The conversion tool checks source paths, output signatures and size before installing any output. All conversions finish before replacement begins. Each installed file uses a unique sibling temporary directory and an atomic rename. Replacement of the whole corpus is **not transactional**: a disk or permission failure during installation may require a rerun. Do not run simultaneous builds into the same destination. The timeout kills the direct converter process; process-tree termination on every platform is not established.

The generated bytes were inspected separately with ZIP CRC/XML checks and PDF structure checks. Signature checks in the builder alone do not prove a valid document or preserve semantic features. Reader owners must add and review expected JSON and Markdown; this tool never generates goldens.

Known conversion gaps (observed while building these fixtures):

- ODF hidden sheets become XLSX `hidden`; a distinct `veryHidden` state is not preserved.
- The PNG is embedded, but its source title/description is lost from DOCX image alternative text.
- ODF title frames become text boxes without PowerPoint title placeholders.
- The source's two-column declaration is unsuitable for a reliable two-column PDF layout assertion.
- Page labels and explicit PDF outlines require additional fixture sources.

To add Microsoft Office or Google Docs exports, the owner must explicitly dedicate the synthetic document to CC0-1.0. Record `SPDX-License-Identifier: CC0-1.0`, the owner statement, export tool/version, original source, and intended requirements in a sidecar. Do not import organizational or private documents. Reader owners review the feature content and goldens before registration.
